## 阶段 1：摸清赛方提供的资产（关键，1 天）

拿到并整理成清单，这决定了后面所有接口设计：

1. **四个 PyAether 脚本源码**
   - 尺寸 → 变量（参数化电路图，生成 `schematic_var`）
   - 读取器件连接关系（打印 Gate/Source 接的 Net 名）
   - 调用 MDE 仿真、提取性能指标
   - 最优尺寸反标（生成 `schematic_var_best`）
2. **参数文件格式**：`extractcdfVal_0.txt` —— 我们的优化器输出必须与它**完全同格式**，这是最硬的接口
3. **MDE 配置**：`mde_cell=input_OPA_LoopGain`、`mde_view=input_spe_state1_corner`，以及 PVT corner 清单（TT/FF/SS × -40/0/125℃ × 标称电压 ±10%）
4. **PDK 取值约束**：W 0.13–20μm、L 0.13–10μm、m 1–20 整数、R Seg 1–20 整数、C L 0.13–20μm
5. **真实网表 / 电路图** → 导回本地，校准第②问的识别规则与变量命名（对齐 `NM1_m` 这类命名规则）

产出物：`docs/server_assets.md`（文件清单 + 接口规格说明），队友照此对接口。

## 阶段 3：第③问 优化算法（最紧的时间预算）

- **预算倒推**：3 小时总时限，留 20% 余量 → 用「单次仿真耗时」算出可用评估次数 N
- **算法选型**：以差分进化（DE）为主干 + 约束处理（PM/GM/I_OPA 用可行性规则或惩罚函数）；变量经第②问约减后维度低，DE 收敛快、无梯度依赖、易于并行
- **备选**：贝叶斯优化（评估次数极少时更省预算）、模拟退火
- **多目标处理**：先用硬约束筛出可行解，再按 DC Gain ↑ / UGB ↑ / Area ↓ 排序（评分是分别排名按比例给分，不是加权求和）
- **冷启动**：从官方初始解附近小范围搜索，避免大范围随机导致前期全不可行
- **工程要求**：优化过程**必须落盘日志+中间结果**（VPN 可能掉线，要能续跑）；记录运行次数、时间、内存（评分项 6）

## 阶段 4：第④问 自动化链路与交付物

一条命令跑完全流程：参数化 → MDE 仿真 → 指标提取 → 优化迭代 → 反标 → 全 PVT 验证 → 报告。

交付物对照（评分表）：

| 输出 | 文件 |
|---|---|
| 最优器件尺寸 | `.csv`（如 `M1_w=36u,M1_L=2u`） |
| 带变量电路图 | `schematic_var` |
| 反标后电路图 | `schematic_var_best` |
| 仿真验证报告 | 全 PVT 结果 + 波形（TT/FF/SS × 高低温 × ±10% 电压） |

## 风险与对策

| 风险 | 对策 |
|---|---|
| 3 小时内仿真次数不够 | 参数约减降维 + 提高单次仿真效率 + 早停/代理模型 |
| `param_file` 格式不匹配导致仿真失败 | 阶段 1 先抓样例，写格式校验器，先跑通 1 次再上优化 |
| Hidden 电路结构与 Public 不同 | 识别规则保持通用，**禁止硬编码器件名/模块名** |
| VPN / VNC 掉线 | 优化脚本后台运行 + 日志落盘，支持断点续跑 |
| 多人共用同一账号 | 只在自己 home 目录操作，避免并发跑重负载 |
